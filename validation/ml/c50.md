# C5.0 Decision Trees

**Not R-pinned.** R's `C50` package is not installed on the validation machine, so no number is compared with
C5.0 output. The implementation follows Quinlan (1993, 1996) and is not checked against R's C50 package.

## Method (as implemented)

A C5.0-style classifier for numeric features:

- **Thresholds.** For each feature, the cut with the largest weighted information gain (nats) among those that
  leave at least `min_cases` case weight on each side, at the midpoint between two observed values (the first cut on
  ties).
- **MDL correction** (Quinlan 1996). The gain is lowered by `ln(N_f - 1) / W`, with `N_f` the distinct values of
  the feature in the node and `W` the node weight.
- **Attributes** (C4.5 Release 8). Among the features with positive penalised gain, those with at least the
  average penalised gain compete on gain ratio (penalised gain / split information); the largest ratio wins, the
  first feature on ties. With none, the node is a leaf.
- **Pruning.** Each node's estimated errors are its weighted errors plus added errors from C4.5's `AddErrs`
  formula at confidence `cf`, with the exact `z = qnorm(1 - cf)` in place of C4.5's interpolated deviate table
  (at `cf = 0.25` C4.5's table gives `z` of about 0.6925, `qnorm(0.75)` is 0.6745); a subtree is replaced by a leaf when the leaf's estimate is at most the sum
  of its children's plus 0.1 (C4.5's replace-if-no-worse test). `0 < cf < 1` is required. Subtree raising is not
  implemented.
- **Boosting** (`trials > 1`). AdaBoost.M1 case weights (not C5.0's own boosting scheme), rescaled to mean 1 per
  trial; they enter every count of the next tree (majority class, entropy, gains, split information, error
  estimates, stopping and class probabilities), so the trials grow different trees.
- **Winnowing.** Keeps the features above the 25th percentile of a first tree's importance (a heuristic, not
  C5.0's winnowing).
- **Importance.** The sum of the gain ratios of the splits on each feature in the final, pruned trees of every
  trial, normalised to 1 (not `C5imp`'s usage).
- **Not implemented.** Fuzzy thresholds (the `fuzzy_threshold` option was removed), subtree raising, categorical
  features, C5.0's rule-set simplification and misclassification costs.

## Release notes

C5.0 trees change: thresholds by gain with the MDL correction, attributes by gain ratio above the average gain,
pruning with C4.5's added-errors formula at the exact `qnorm(1 - cf)` and its 0.1 slack. Boosting trials now grow different trees.
`cf` outside (0, 1) is refused. Importance counts only the splits of the final trees. Rules name features and
classes. `fuzzy_threshold` is removed from `C50Config`.

## Target types and missing values

- **Target.** `run_c50` (and `ml_c50`) takes non-negative integer class codes from an
  integer or decimal column, or a text, categorical or boolean column. Labels become the
  codes 0..K-1 in R `factor()` order (text in byte order, which is R's order under
  `LC_COLLATE=C`; FALSE < TRUE) and are reported in `C50Result::class_names` (JSON
  `class_names`, `null` for a numeric target) and a "Class labels: 0 = no, 1 = yes" line of
  the Display. Predictions and `class_labels` stay codes; rules print feature and class names
  (JSON rule `conditions` such as `x1 <= 3.2500`, and `predicted_class_name` for a labelled target).
- **Missing values.** A missing value (null or NaN) in the target or a feature is an
  error naming the column (Fail; p2a's trees have no surrogate splits). `±Inf` is refused
  as well.
- **Tests.** `test_na_c50_class_labels`, `test_na_extract_x_classes_levels`,
  `test_na_ml_wrappers_int64_target_equals_float64` and
  `test_na_ml_wrappers_refuse_missing_values` (`crates/p2a-core/src/ml/extract.rs`),
  `test_na_mcp_tree_tools_integer_and_missing_targets` and
  `test_mcp_c50_ctree_text_targets` (`crates/p2a-mcp/src/tools/handlers/ml.rs`). They
  compare p2a with p2a (a text target against the same classes as integer codes) and pin
  no R number.
