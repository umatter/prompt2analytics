# Validation of prompt2analytics

p2a's numbers are checked against R in two ways, and the generated status page
([VALIDATION_STATUS.md](VALIDATION_STATUS.md)) says which methods are in which:

- **R-pinned tests.** A `test_validate_*` test loads a committed R reference case
  (`validation/expected/<case>.json`, computed by `validation/r/cases/*.R` on a committed or
  generated dataset). It compares every number the method reports with
  `p2a_validation::Check` at the tolerances below, and it is registered in
  `validation/methods/*.json`.
- **Other `test_validate_*` tests**: property, DGP-recovery or quoted-value checks. They are
  useful, but they compare no committed R output. `VALIDATION_STATUS.md` lists them as "not
  registered as R-pinned".

The tolerance table below applies to R-pinned tests only. Most other `test_validate_*` tests
use looser, hand-picked bounds, and a method may be described as matching R only when a
registered test pins it.

## Layout

```
validation/
├── README.md                 # this file
├── VALIDATION_STATUS.md      # generated by tools/validation_status.py render; never edited by hand
├── reference_implementations.md
├── run_validation.sh         # test_validate tests in the CI feature sets + R drift check
├── r/harness.R               # case(), named(), vec(), dataset CSV and case JSON writers, comparator
├── r/run.R                   # --check [ids] | --write [ids] | --list
├── r/cases/<area>.R          # R reference cases, one file per area (harness_selftest, regression,
│                             #   regression_legacy, panel, discrete_newton)
├── expected/<case>.json      # one R reference case per file (schema 1)
├── expected/*.csv            # legacy outputs of scripts/*.R; asserted only where a registry entry supersedes them
├── methods/<area>.json       # registry: method -> cases, tests, quantities, tolerance, deviations (see methods/README.md)
├── datasets/                 # committed reference data; datasets/generated/ is written by R cases (see datasets/README.md)
├── tools/                    # validation_status.py (select | collect | lint | render), lint_ignore_names.txt, tests/
├── scripts/*.R               # legacy R scripts; run only with run_validation.sh --legacy-r, in scratch directories
├── r_comparison/             # legacy one-off comparison scripts (feglm, survival, synth); not run by the runner
├── reports/                  # run output (gitignored)
└── <category>/<method>.md    # method documents: regression/, diagnostics/, econometrics/ (+ timeseries/),
                              #   forecasting/, timeseries/, stats/, multivariate/, ml/, linalg/
```

## Running

```bash
validation/run_validation.sh                         # all test_validate tests (CI feature sets) + Rscript validation/r/run.R --check
validation/run_validation.sh --rust-only --category econometrics   # stats | regression | econometrics | forecasting | ml | cli | mcp
validation/run_validation.sh --r-only                # R drift check only: Rscript validation/r/run.R --check
validation/run_validation.sh --write-status          # also regenerate VALIDATION_STATUS.md from this run (full runs only)
validation/run_validation.sh --legacy-r              # also run scripts/*.R (informational; never counted as passed)
Rscript validation/r/run.R --check                   # recompute every case in a temp dir; exit 1 on any difference > 1e-12 relative
Rscript validation/r/run.R --write ols_grunfeld      # (re)write one case JSON and the datasets it generates
Rscript validation/r/run.R --list
cargo test -p p2a-core --lib --no-default-features --features ci -- regression::ols::tests::test_validate
cargo test -p p2a-core --lib --no-default-features --features ci -- econometrics::hdfe::tests::test_validate
cargo test -p p2a-validation
python3 validation/tools/validation_status.py lint --strict --tests target/*-tests.txt
```

The Rust step lists the tests of p2a-core, p2a-cli and p2a-mcp on CI's feature sets
(`cargo test -p <pkg> --tests -- --list`), keeps the `test_validate` tests, selects a
category by module path and test binary (`validation/tools/validation_status.py select`),
and runs them with `--exact`, plus every self-test of `p2a-validation`. A compile error, a
failing test, fewer tests run than selected, a selected test without a parsed result, or no
selected `test_validate` test is a failure. Full runs also lint the methods registry. The R
step recomputes every R reference case (see "Adding an R-pinned validation" below).
`--legacy-r` runs each legacy script in a
scratch directory with a copy of `validation/datasets`, so tracked files are never written,
and compares the CSVs it produces with `validation/expected/*.csv`.

Exit codes of `run_validation.sh`: 0 PASS, 1 FAIL (including a compile error or zero
selected tests), 2 usage error, 3 INCOMPLETE (`cargo` or `Rscript` missing for a requested
step). Results go to `validation/reports/<timestamp>-<pid>/` (gitignored): the logs,
`results.json` and `report.md`; both record the commit, marked `-dirty` when tracked files
differ from it. `--write-status` describes the whole suite, so it is refused (exit 2) with
`--category`, `--rust-only` or `--r-only`, and a run in which a selected test has no parsed
result leaves the page as it was. `--release`, `--verbose` (`-v`) and the environment
variables `P2A_RSCRIPT`, `P2A_LEGACY_R_TIMEOUT` (whole seconds >= 1, default 300; read only
with `--legacy-r`) and `PYTHON` are also accepted. `--verbose` shows the cargo output and
every comparison a `Check` makes, which libtest prints after the test status lines
(`--show-output`). The runner sets `CARGO_TERM_COLOR=never` for cargo, since it parses
cargo's output. In a direct cargo run, set `P2A_VALIDATION_VERBOSE=1` to print every
comparison a `Check` makes.

Direct cargo filters are substrings of the libtest path, not regexes. Module paths such as
`regression::ols::tests::test_validate`, `econometrics::panel::tests::test_validate` and
`econometrics::hdfe::tests::test_validate` are stable where individual test names are not
(the paper's Makefile uses them).

`VALIDATION_STATUS.md` is regenerated once per wave integration, after the lanes are merged
(`validation/run_validation.sh --write-status`), and never edited by hand. CI's status-page
check (`P2A_CHECK_STATUS_PAGE=1`, `validation/tools/tests/test_status_page.py`) fails when the
page's per-package `test_validate` counts differ from `cargo test -- --list`.

## Prerequisites

The Rust half needs only a toolchain meeting the workspace MSRV. The R half needs R >= 4.3
and the packages below; a missing one surfaces as `there is no package called 'x'`, which
looks like a validation failure but is not one.

- **Harness** (`validation/r/harness.R` and `validation/r/cases/*.R`; the case files record
  the versions they were written with): jsonlite, plm, fixest, sandwich, lmtest, car, tseries,
  quantreg, nlme, aod, strucchange, nnet, MASS.

  ```r
  install.packages(c("jsonlite", "plm", "fixest", "sandwich", "lmtest", "car", "tseries",
                     "quantreg", "nlme", "aod", "strucchange", "nnet", "MASS"))
  ```

- **Legacy scripts** (`validation/scripts/*.R`, run only with `--legacy-r`): AER, aod, BART,
  boot, car, e1071, EValue, forecast, gbm, glmnet, lightgbm, lmtest, MASS, MatchIt, mboost,
  medflex, mediation, microbenchmark, nlme, nnet, optmatch, pdp, plm, pROC, pscl, quantreg,
  randomForest, rdrobust, rpart, sandwich, survival, tmle, tseries, vars, WeightIt, xgboost.
  `car`, `tseries`, `forecast` and `survival` are required by `scripts/run_all_validations.R`.
  `optmatch` is not loaded directly by any script but is required by `MatchIt` for full
  matching. A legacy script whose package is missing is reported as "error"; that never fails
  a run.

Reference packages change their return shapes over time (in 2026-08 `mediation` dropped
`$tau.var` and `WeightIt` dropped `$ess`). When a legacy script fails, check whether the R
package changed before suspecting p2a-core. For the R cases, an upgrade that changes a value
fails `run.R --check`, which is the point: re-check the method and rewrite the case with
`--write` only when the new value is the right one.

## Adding an R-pinned validation

This is the workflow every new or fixed validation follows.

1. **Write a case.** Add a `case()` to `validation/r/cases/<area>.R`:
   - One `case(id, area, method, function(ctx) ...)` per reference; `id` matches
     `^[a-z0-9_]+$`, is the JSON file name and starts with the area's prefix (`ols_`,
     `panel_`, `diag_`, `step_`, `hac_`, `disc_`, ...).
   - Use the R function named in the method's reference column
     ([reference_implementations.md](reference_implementations.md)), never a
     re-implementation, except as an extra cross-check value.
   - Read committed data with `ctx$dataset("datasets/grunfeld.csv")` (relative to
     `validation/`). Simulated data: `set.seed(<fixed>)` inside the case, then
     `ctx$gen_dataset(name, df)`, which writes `validation/datasets/generated/<name>.csv` with
     round-trip precision and reads it back, so R computes on the doubles Rust will read. Data
     must have noise.
   - Return `list(values = ..., reference = ..., call = ..., packages = ...)`, with `packages` a
     character vector of the R packages the case uses (each version is recorded); a
     base-R-only case returns `character(0)`, which is written as `"packages": {}`. `NULL`,
     `NA` and empty names are refused. Named vectors (coefficients, SEs, CI bounds) go through
     `named(x)`, unnamed arrays through `vec(x)`, scalars as plain numbers; `NA` becomes `null`
     (NaN in Rust).
   - Add `stopifnot()` checks for the property the case exists to exercise.
2. **Write and check it.** Run `Rscript validation/r/run.R --write <id>`, then `--check`.
   `--check` fails (exit 1) when a recomputed value differs from the committed file by more
   than 1e-12 relative, changes its kind (scalar, unnamed array or named vector), its names or
   the position of an `NA`, when a generated dataset differs, when a committed case has no
   definition, or when a generated dataset belongs to no case. R writes tracked files only
   under `--write`.
3. **Write the test** `test_validate_<method>_<dataset>[_<variant>]` in the module it tests.
   Use `crate::test_support::load_case("<id>")` (p2a-core) or `p2a_validation::Case::load`
   (p2a-cli, p2a-mcp), and `p2a_validation::{Check, Tol}`. Pin every number the method
   reports for that call. No `if let Ok`, no print-only checks.

   ```rust
   #[test]
   fn test_validate_panel_re_grunfeld() {
       use p2a_validation::{Check, Tol};
       let (case, ds) = crate::test_support::load_case("panel_re_grunfeld");
       let r = run_random_effects(&ds, "inv", &["value", "capital"], "firm").unwrap();
       let n = r.n_obs;
       Check::new(&case)
           .named("coef", &r.variables, &r.coefficients, Tol::coef(n))
           .named("se", &r.variables, &r.std_errors, Tol::se(n))
           .scalar("df_resid", r.df as f64, Tol::exact())
           .finish();
   }
   ```

   `load_case` reads the case and loads its dataset with `DataLoader::load_csv`, the loader
   `p2a data load` uses. `Check` compares every value, collects all failures and panics once
   listing them; it also panics when nothing was compared or when `finish()` is missing. CLI
   exhibit tests compare their output with committed golden files through
   `p2a_validation::golden::assert_golden`; regenerate those with `P2A_UPDATE_GOLDEN=1` only
   after the numbers in the output were checked against R (`p2a_validation::text` parses the
   coefficient table). `P2A_REPO_ROOT` points the crate at another checkout.
4. **Register it** in `validation/methods/<area>.json` with cases, tests, quantities,
   tolerance and deviations ([methods/README.md](methods/README.md)). `validation_status.py
   lint` fails for a test that loads a case and is not registered with it.
5. **Update the method document** and this README's index row.
6. **Run** `python3 validation/tools/validation_status.py lint --strict --tests
   target/*-tests.txt` and `validation/run_validation.sh`.
7. **Regenerate the status page.** Adding, removing or renaming a `test_validate` test
   changes the counts CI checks: regenerate `VALIDATION_STATUS.md` with
   `validation/run_validation.sh --write-status` before the change reaches main (during the
   review campaign: at the wave integration, not in a lane).

A mismatch is a defect. Fix it, or record a deviation `{"finding", "quantity", "note"}` in the
registry and keep that quantity out of the `Check` with a `// deviation <finding id>` comment.
Never widen a tolerance to make it pass.

## Tolerances (`p2a_validation::Tol`)

| Quantity | `Tol` | n < 100 | 100 ≤ n ≤ 1000 | n > 1000 | abs |
|---|---|---|---|---|---|
| coefficients | `Tol::coef(n)` | 1e-6 | 1e-8 | 1e-10 | 1e-12 |
| standard errors | `Tol::se(n)` | 1e-5 | 1e-6 | 1e-8 | 1e-14 |
| test statistics, R², F, χ², logLik/AIC/BIC, variance components, CI bounds | `Tol::stat(n)` | as SE | as SE | as SE | 1e-14 |
| p-values | `Tol::p_value(n)` | SE rel | SE rel | SE rel | 1e-12 |
| iterative estimators (MAP, MLE) | `Tol::iterative(rel)` | documented per test | | | 1e-12 |
| CLI text printed with d decimals | `Tol::printed(d)` | rel 0 | | | 0.5·10^-d + 1e-12 |
| counts and degrees of freedom | `Tol::exact()` | exact | | | |

All values are relative unless stated: |actual − expected| ≤ abs + rel·|expected|. NaN equals
NaN; ±inf equals only itself. `Tol::iterative(rel)` and `Tol::new` need a comment giving the
reason. `Tol` (in `crates/p2a-validation/src/check.rs`) and this table must agree; change both
or neither.

## Method document format

Each method has a Markdown file in its category directory with these sections:

1. **Method Overview**: brief description and key parameters.
2. **Reference Implementations**: the packages used for comparison, with versions.
3. **Test Cases**: dataset description, R code for reproduction, R's results.
4. **R reference**: `validation/r/cases/<file>.R`, case `<id>`.
5. **Rust tests**: libtest paths (`cargo test -- <path>` accepts them) and what each checks.
6. **Tolerance**, with the `Tol` used.
7. **Status**: R-pinned (registry `validation/methods/<area>.json`, id `<id>`), or not R-pinned
   (with the finding that adds the case).
8. **Known Differences**: deviations from the reference, each with its finding id.
9. **References**: academic citations.

No `~` values in comparison tables, no hand-written `#[test]` code: cite the tests that exist.
