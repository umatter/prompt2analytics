# VARMA(p, q) by Hannan-Rissanen

Registry: [`validation/methods/ts_varma.json`](../../methods/ts_varma.json) (method `ts_varma`).
R case: `varma_hr` in [`validation/r/cases/ts_varma.R`](../../r/cases/ts_varma.R).

`run_varma(dataset, columns, p, q)` and `run_varma_with(dataset, columns, &VarmaConfig)` in
`crates/p2a-core/src/econometrics/timeseries/varma.rs`. MCP `ts_varma`; CLI `p2a ts varma`.

## Model and estimator

Standard-form VARMA with every coefficient free:

```
y_t = c + A_1 y_{t-1} + ... + A_p y_{t-p} + u_t + M_1 u_{t-1} + ... + M_q u_{t-q}.
```

Hannan & Rissanen (1982) two-step estimator:

1. **Step 1 (q > 0).** Fit a long VAR(m) with intercept by OLS on t = m + 1..n. Its residuals ê_t
   estimate u_t. Only the residuals are needed, so the diagonally equilibrated normal equations are
   solved by Cholesky; when the factorisation fails or the ratio of its largest to its smallest
   diagonal entry exceeds 1e4, the pivoted QR of `stats::lm.fit` is used instead (an aliased lag
   then gets the warning "long VAR (step 1): Coefficients not defined because of singularities: ..").
   The step-2 coefficients that follow agree with the R case (`lm.fit` throughout) to about 1e-14.
2. **Step 2.** For each equation, fit OLS of y_t on `[1, y_{t-1..p}, ê_{t-1..q}]` over
   t = m + max(p, q) + 1..n, by the pivoted QR of `lm.fit`. This gives n_eff = n - m - max(p, q)
   observations. statsmodels' `hannan_rissanen` starts at m + q + 1 when m >= p, so for p > q it
   uses p - q more observations; p2a keeps one rule for every (p, q), so that fits at the same m
   share their sample and their criteria compare.

Reported quantities:
- **Coefficients.** In the order `const`, `<v>.l<j>` (as vars names them) and `e.<v>.l<j>`.
  `ar_params` holds the constant and the AR rows; `ma_params` holds the MA rows.
- **Standard errors, t and p values: q = 0 only.** For q = 0 the fit is an OLS VAR and the
  `summary.lm` standard errors (df = n_eff - rank) are valid. For q > 0 they are **not reported**
  (`std_errors` is empty, `t_values()` and `p_values()` return empty vectors, and Display says so):
  the step-2 regressors ê_{t-j} are generated by step 1, and for the AR and constant coefficients the
  step-1 estimation error enters the limiting distribution whenever M != 0 (a generated-regressor
  problem), so the step-2 OLS covariance does not describe it. A Monte Carlo on the case DGP (500
  replications, default m) put the ratio of the mean OLS SE to the empirical SD of the estimate at
  0.86-1.07, lowest (0.86-0.90) for the constant and AR terms of equation y1, whose MA row is non-zero.
- **Sigma_u.** U'U / n_eff (ML).
- **Log-likelihood.** logLik = -n_eff/2 (K ln 2 pi + ln det Sigma_u + K), with ln det Sigma_u from the
  Cholesky factor (the old code used the product of the absolute values of all K^2 entries).
- **Information criteria.** AIC = -2 logLik + 2 npar and BIC = -2 logLik + ln(n_eff) npar, where
  npar = K x rank of the step-2 design. This is the parameter count of `stats::logLik` for
  `vars::VAR`, extended by the MA coefficients.
- An aliased step-2 regressor is NaN (R: NA) with R's warning "Coefficients not defined because of
  singularities: ..", and its name is in `aliased`; SEs (q = 0) and npar use the identified columns.
  `run_var` refuses the same design instead (`SingularMatrix`).

**Long-VAR order m.**

| Situation | m |
|---|---|
| `long_var_order` given | that value. It must be >= 1 when q > 0, and the long VAR must keep a residual degree of freedom. With q = 0 it only moves the sample start, so the criteria compare with VARMA(p, q) fits at the same m. |
| default, q = 0 | 0. The fit is the OLS VAR(p), equal to `vars::VAR(type = "const")`. |
| default, q > 0 | max(floor(ln(n)^2), 2 max(p, q)), from Gómez & Maravall (2001); this is also statsmodels' default. It is reduced to floor((n - 2) / (2K + 1)) with a warning, so that the long VAR keeps at least as many residual degrees of freedom as regressors. |

The T3 design proposed max(p + q, floor(1.5 ln(n)^2)). In a Monte Carlo of the case DGP (200
replications) the 1.5 factor gave a coefficient RMSE of 1.35 at n = 100 against 0.77 for
floor(ln(n)^2), and its long VAR costs about 2.25 times as much.

**Errors.**

| Condition | Error |
|---|---|
| p = q = 0 | `InvalidSpecification` |
| `long_var_order = 0` with q > 0 | `InvalidSpecification` |
| Too few observations for the long VAR (required = m + 1 + K m + 1) or for the step-2 regression (required = m + max(p, q) + 1 + K (p + q) + K: the K x K Sigma_u needs K residual degrees of freedom); no default long VAR fits (n < 2K + 3) | `InsufficientData` |
| Linearly dependent series (Sigma_u of rank < K) | `SingularMatrix` |
| Missing or non-numeric values | `NullValues` / `NonNumericColumn` (Fail policy, as `vars::VAR`) |

**Not implemented:**
- the third (bias-correction) step;
- ML refinement;
- echelon-form identification restrictions. An over-parameterised VARMA with common factors is
  estimated but not detected, and its MA/AR split can be weakly identified.

**Cost.** One long VAR(m), O(n (1 + K m)^2) with m about (ln n)^2, where the old code fitted one
VAR(p). Measured on one P core (release, `RAYON_NUM_THREADS=1`), default VARMA(1, 1): n = 100, K = 2
(m = 19) 0.08 ms; n = 1,000 (m = 47) 2.6 ms; n = 10,000 (m = 84) 70 ms; n = 10,000, K = 5 (m = 84,
421 step-1 columns) 104 ms. Each is below `run_var` at the same m (0.16, 6.8, 324 and 798 ms), which
solves its VAR by pivoted QR.

## R reference

No R package for this estimator is installed (MTS, marima and dse are missing). The estimator is
written out with `lm.fit`/`lm` in `validation/r/cases/ts_varma.R`, case `varma_hr`. The data is a
bivariate VARMA(1,1) with n = 400 and seed 20261114
(`validation/datasets/generated/varma_sim.csv`). For q = 0 the reference is
`vars::VAR(p = 2, type = "const")`. R 4.3.3, vars 1.6.1. The case records standard errors and
p-values for the q = 0 fits only.
